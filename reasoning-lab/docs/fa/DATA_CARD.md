# کارت دادهٔ مجموعهٔ مصنوعی Micro Reasoning Lab

این سند، شناسنامهٔ داده‌های داخل `data/generated/` است. این مجموعه **دادهٔ واقعی، گردآوری‌شده از وب یا حاصل تعامل کاربران نیست**؛ همهٔ رکوردها با یک دستور زبان بسته و یک مولد محلی و قطعی ساخته شده‌اند.

## هویت و قرارداد ماشین‌خوان

| فیلد | مقدار | معنای عملی |
|---|---|---|
| وضعیت | `synthetic: true` | هر world، سند، episode و نمونهٔ آموزشی مصنوعی است. |
| فرمت داده | `reasoning-lab-curriculum-v1` | قرارداد رکوردهای JSONL؛ در این اصلاح تغییر نکرده است. |
| schema مانیفست | `reasoning-lab-dataset-manifest-v2` | نسخهٔ قرارداد metadata و provenance مانیفست. |
| مولد | `reasoning_lab.data.generate_curriculum` | تابع محلی تولید curriculum. |
| schema مولد | `reasoning-lab-curriculum-generator-v1` | قرارداد الگوریتم مولد. |
| نسخهٔ مولد | `1.0.0` | نسخهٔ صریح برای بازپخش و ممیزی. |
| مجوز داده | `CC-BY-4.0` | مربوط به رکوردهای مصنوعی تولیدشده و manifest آن‌هاست. |

مجوز `CC-BY-4.0` فقط به مجموعه‌دادهٔ مصنوعی و manifest اعمال می‌شود؛ مجوز نرم‌افزار، وزن مدل‌ها و وابستگی‌های ثالث را تغییر نمی‌دهد. هنگام بازنشر داده، نام «Micro Reasoning Lab contributors» و پیوند پروژه را به‌عنوان attribution نگه دارید.

## محتوا و اندازهٔ snapshot فعلی

| بخش | تعداد episode | نقش |
|---|---:|---|
| `train` | ۱۲۰۰ | آموزش در عمق‌های درون‌توزیع |
| `validation` | ۱۶۰ | انتخاب و پایش درون‌توزیع |
| `iid_test` | ۱۶۰ | آزمون مستقل درون‌توزیع |
| `depth_ood` | ۱۲۰ | آزمون عمق خارج از توزیع آموزش |
| `rag_holdout` | ۸۰ | آزمون بازیابی facts حذف‌شده از prompt |

هر episode سه نمای آموزشی `direct`، `scratch` و `tool` دارد. worldها مقادیر متغیرهای `A` تا `H` را در بازهٔ صفر تا نه نگه می‌دارند؛ عبارت‌ها فقط از `ADD`، `SUB` و `MUL` با محاسبهٔ پیمانهٔ ۱۰ ساخته می‌شوند. اسناد RAG نیز بازنمایی مصنوعی همین worldها هستند، نه متن برگرفته از منبع بیرونی.

## منشأ، ورودی و seed

```text
DataConfig + tokenizer ثابت + دستور زبان بسته
                    │
                    ├── master seed: 20260830
                    │       └── split seed = 8 بایت نخست SHA-256("seed:split")
                    │
                    └── generate_curriculum → JSONL قطعی → SHA-256 manifest
```

- ورودی بیرونی: هیچ corpus، خروجی مدل ثالث یا دادهٔ شخصی/کاربری وارد مولد نمی‌شود.
- منبع تصادف: برای هر split یک نمونهٔ مستقل `random.Random` با split seed قطعی ساخته می‌شود.
- tokenizer: واژگان بسته و ثابت است؛ hash آن در manifest ثبت می‌شود.
- پارامترهای قابل بازبینی: master seed، شمار هر split، hash tokenizer و فایل‌ها در `data/manifests/dataset-manifest.json` موجود است.
- ورودی کامل `DataConfig`: تعداد episodeهای هر split، `train_max_depth`، `ood_depth` و `max_distractors` نیز زیر `provenance.inputs.generation_parameters` ثبت می‌شوند.
- بازپخش معتبر باید از نسخهٔ ثبت‌شدهٔ مولد و محیط قفل‌شدهٔ پروژه استفاده کند و سپس hashها را مقایسه کند.

## تمامیت و بازپخش

شناسهٔ محتوای snapshot فعلی:

```text
dataset_sha256 = f00f2cbb726ea9035e6fa4b0dc08cd2510324d34f3937e5659c700f65b911441
```

`dataset_sha256` از محتوای curriculum محاسبه می‌شود و metadata کارت/manifest را وارد محاسبه نمی‌کند. در نتیجه افزودن provenance، بایت‌های JSONL و شناسهٔ محتوای داده را تغییر نمی‌دهد. `SHA256SUMS` hash دقیق تک‌تک فایل‌های JSONL و خود manifest را ثبت می‌کند؛ hash manifest با هر تغییر metadata به‌درستی عوض می‌شود.

برای بازسازی و آزمون:

```powershell
uv run reasoning-lab build-data
uv run pytest tests/test_task_data.py
```

## کاربردهای هدف

- آموزش و مشاهدهٔ مرحله‌به‌مرحلهٔ tokenization، آموزش، inference، RAG و tool use در یک مسئلهٔ بسته و کوچک؛
- آزمایش‌های قطعی واحد، یکپارچه و مقایسه‌ای در همین دستور زبان؛
- بررسی تفاوت split درون‌توزیع، عمق خارج‌از‌توزیع و retrieval holdout؛
- نمونهٔ آزمایشگاهی برای توضیح تفاوت «حفظ‌کردن»، «محاسبه‌کردن» و «بازیابی‌کردن».

## کاربردهای خارج از هدف

- سنجش یا رتبه‌بندی توان عمومی یک مدل زبانی؛
- تصمیم‌گیری تولیدی، ایمنی‌بحرانی، پزشکی، حقوقی، مالی یا سیاست‌گذاری؛
- نتیجه‌گیری دربارهٔ واقعیت جهان، زبان طبیعی، افراد، فرهنگ‌ها یا جمعیت‌ها؛
- ادعای نبود سوگیری یا اثبات ایمنی مدل‌های واقعی؛
- جایگزینی benchmarkهای استاندارد، دادهٔ واقعی دارای رضایت، یا ارزیابی انسانی.

## محدودیت‌ها و ریسک تفسیر

دامنهٔ صفر تا نه و دستور زبان مصنوعی عمداً بسیار کوچک‌اند. عملکرد خوب می‌تواند از الگوهای کوتاه، پوشش ترکیبی یا استفاده از ابزار حاصل شود و نباید به reasoning عمومی تعمیم داده شود. نبود دادهٔ انسانی، ریسک افشای PII در خود generator را حذف می‌کند، اما به‌تنهایی چیزی دربارهٔ privacy یک مدل یا سامانهٔ دیگری ثابت نمی‌کند. splitهای مستقل و آزمون leakage بخشی از کنترل‌اند، نه گواه بی‌نقص‌بودن همهٔ انواع contamination.

## نگه‌داری و تغییر نسخه

- تغییر فقط در توضیحات provenance: schema مانیفست و hash manifest باید به‌روزرسانی شود؛ hash داده می‌تواند ثابت بماند.
- تغییر رکورد، دستور زبان، tokenizer یا الگوریتم تولید: نسخهٔ فرمت/مولد باید بازبینی شود و hash داده باید دوباره تولید شود.
- هر snapshot منتشرشده باید همراه `dataset-manifest.json`، `dataset-manifest.sha256`، `SHA256SUMS` و همین Data Card باشد.
- ادعاهای آموزشی باید همواره وضعیت «واقعی»، «شبیه‌سازی» یا «نیازمند شاهد بیرونی» را جدا نگه دارند.
