# راهنمای اطلس دیداری مدل و تصمیم

این سند راهنمای خواندن رابط زندهٔ آزمایشگاه است. هدف آن نسبت‌دادن یک توضیح علّی
به شبکه نیست؛ هدف این است که دادهٔ مشاهده‌شده، محاسبهٔ مدل، کمک بیرونی، تصمیم
میزبان و پاسخ مرجع با یکدیگر مخلوط نشوند.

## راهنمای رنگ و شکل

| منشأ | شکل غالب | معنی | چه ادعایی مجاز نیست؟ |
|---|---|---|---|
| دادهٔ ورودی | دایره و فیروزه‌ای | واقعیت یا توکنی که از مسئله آمده است | دادهٔ ورودی «دانش داخل وزن» نیست |
| محاسبهٔ مدل | چهارگوش سبز اسیدی | وزن، attention، MLP، router یا توزیع مدل | telemetry توضیح علّی یا فکر پنهان نیست |
| کمک بیرونی | چهارگوش نارنجی | سند RAG یا ابزار خارج از checkpoint | بهبود آن نباید فقط به مدل نسبت داده شود |
| تصمیم میزبان | ذوزنقه و زرد | parser، constraint، candidate selector یا controller | این تصمیم، توانایی آموخته‌شدهٔ مدل نیست |
| مرجع ارزیابی | قرمز | Oracle و پاسخ صحیح پس از پایان inference | Oracle یک مدل مقایسه‌ای نیست |

تمام نمودارها یک جدول متنی جایگزین دارند؛ بنابراین رنگ تنها حامل معنا نیست.

## پیش از inference: رابطهٔ داده، آموزش و وزن‌ها

```text
قواعد DSL + seed ثابت
          │
          ▼
۱٬۷۲۰ episode در ۵ split
          │
          ▼
Tokenizer ثابت و بدون UNK
          │
          ▼
۵٬۱۶۰ نمونهٔ direct / scratch / tool
          │
          ▼
loss mask: فقط targetهای تعریف‌شده در gradient
          │
          ▼
AdamW و آموزش وزن‌ها از مقداردهی اولیهٔ تصادفی
          │
          ▼
۵ checkpoint هش‌شده پس از اجرای `train-all`
```

این پروژه fine-tune یک مدل بزرگ آماده نیست. مدل‌های عصبی آن از صفر و روی corpus
آزمایشگاهی آموزش دیده‌اند. Parser، Oracle، کنترل‌گر ابزار و پایگاه RAG داخل وزن‌ها
یاد گرفته نشده‌اند. برای objective نوع scratch، کل payload هدف در آموزش supervised
است؛ هنگام inference قاب نحوی میزبان و نمونه‌گیری slotهای رقمی از هم جدا ثبت می‌شوند.

| Split | تعداد | هدف | در gradient آموزش؟ |
|---|---:|---|---|
| `train` | ۱٬۲۰۰ | یادگیری وزن‌ها | بله |
| `validation` | ۱۶۰ | کنترل روند آموزش | خیر |
| `iid_test` | ۱۶۰ | آزمون هم‌توزیع | خیر |
| `depth_ood` | ۱۲۰ | عمق بیشتر از آموزش | خیر |
| `rag_holdout` | ۸۰ | واقعیت‌های نگه‌داشته‌شده برای retrieval | خیر |

## هفت برش اطلس زنده

| مرحله | ورودی | عمل | خروجی | پرسشی که پاسخ می‌دهد |
|---|---|---|---|---|
| ۱. صورت مسئله | واقعیت‌های A تا H و عبارت | parse قطعی DSL | AST و متغیرهای مصرف‌شده | کدام داده واقعاً به پاسخ مربوط است؟ |
| ۲. توکن‌سازی | prompt متنی | longest-match | ID و منشأ هر توکن | شبکه دقیقاً چه اعدادی می‌گیرد؟ |
| ۳. ساخت زمینه | عبارت و mode | prompt، retrieval، ابزار یا Oracle | زمینهٔ قابل دسترس | دانش از وزن آمده یا بیرون؟ |
| ۴. محاسبهٔ فعال | توکن‌های زمینه | N-gram، MLP، Transformer یا MoE | logitهای توکن بعدی | کدام الگوریتم واقعاً اجرا شد؟ |
| ۵. تولید | logit و سیاست decoding | constraint، temperature و sampling | توکن‌ها یا رویدادهای ابزار | چه چیزی را مدل ساخت و چه چیزی را میزبان؟ |
| ۶. انتخاب | کاندیداها | protocol، verifier، majority و logprob | یک مسیر منتخب | چرا این کاندیدا برنده شد؟ |
| ۷. نتیجه | پاسخ منتخب | مقایسهٔ پس از inference با Oracle | درست/نادرست و هزینه | از این اجرا دقیقاً چه می‌توان نتیجه گرفت؟ |

## چهار مسیر واقعی اجرا

```text
MODEL ONLY : input → tokenization → model → candidates → [verifier] → answer
RAG        : input → retrieval → injected prompt → model → candidates → [verifier] → answer
TOOLS      : input AST → scripted controller → LOOKUP/CALC → answer
ORACLE     : input AST → deterministic evaluator → answer
```

براکت `verifier` یعنی این جزء فقط برای objective نوع scratch کاربرد دارد. در مدل
direct، معتبر بودن پروتکل scratch معنایی ندارد. در Tools و Oracle نیز معماری و
effort غیرفعال‌اند، چون شبکهٔ زبانی فراخوانی نمی‌شود.

## پنج الگوریتم به زبان ساده

| روش | تصویر ذهنی درست | چه چیزی دارد؟ | محدودیت شاخص |
|---|---|---|---|
| N-gram | جدول «این دنباله چند بار با چه توکنی ادامه یافت؟» | count و backoff | رابطهٔ دور یا ترکیبی را صریح مدل نمی‌کند |
| Window MLP | هشت کارت آخر به یک بردار بزرگ چسبانده می‌شوند | embedding و MLP | بیرون پنجره را مستقیم نمی‌بیند |
| Dense direct | هر توکن به گذشتهٔ مجاز نگاه می‌کند | attention و FFN متراکم | فقط رقم جواب supervision می‌گیرد |
| Dense scratch | همان Transformer با خانه‌های عددی میانی | trace عمومی و verifier | قاب نحوی trace را میزبان می‌سازد |
| Sparse MoE | router برای هر token×layer یک راهرو را باز می‌کند | چهار expert و Top-1 | expert عامل یا ذهن مستقل نیست |

## خواندن تله‌متری پیشرفته

### گزینه‌های توکن

نوارها توزیع پس از محدودسازی توکن‌های مجاز، temperature و top-k هستند. قاب سبز
توکن واقعاً انتخاب‌شده را مشخص می‌کند؛ این توکن در sampling لزوماً بیشترین احتمال
را ندارد. پنج گزینهٔ اول نیز لزوماً مجموع ۱۰۰ درصد نیستند.

### Attention

سطر، توکن خروجی و ستون، توکن قبلی است. شدت خانه وزن اتصال را در آخرین لایه، پس
از میانگین‌گیری headها و روی snapshot نهایی کاندیدای منتخب نشان می‌دهد. این ماتریس
«علت قطعی» پاسخ نیست.

### MoE

`token×layer` واحد درست شمارش است: یک توکن در دو لایه می‌تواند دو بار route شود.
جدول مرحلهٔ معماری، موقعیت، متن توکن، expert منتخب و احتمال gate را نشان می‌دهد.
`E0..E3` فقط شناسهٔ شبکه‌های MLP هستند.

### RAG

Query، رتبهٔ سند، متغیر، مقدار، محتوای سند، URI منشأ و score خام FTS5 نمایش داده
می‌شوند. سند بازیابی‌شده داخل وزن checkpoint قرار نمی‌گیرد؛ به prompt تزریق می‌شود.
در اجرای تعاملی فعلی، facts همان درخواست ابتدا به اسناد همان world تبدیل می‌شوند؛ این
fixture بسته نباید «کشف دانش ناشناخته از corpus مستقل» نامیده شود.

### Tools

هر ردیف یک `CALL → OBS` واقعی است: نام ابزار، آرگومان typed، نتیجه، وضعیت و زمان.
در این آزمایش controller اسکریپتی و `learned_policy=false` است.

### انتخاب کاندیدا

ترتیب معیارها واژه‌نامه‌ای است:

1. اعتبار کامل پروتکل؛
2. امتیاز verifier؛
3. تطابق با پاسخ اکثریت؛
4. normalized log probability؛
5. اندیس زودتر برای شکستن تساوی.

این سیاست میزبان است، نه تصمیم پنهان در وزن‌ها.

## مثال خواندن یک اجرا

برای `A=3`، `B=5`، `C=2` و `MUL(ADD(A,B),C)`، مرجع قطعی چنین است:

```text
GET A 3
GET B 5
ADD 3 5 8
GET C 2
MUL 8 2 6
```

پس پاسخ مرجع ۶ است. اگر مدل مثلاً ۴ تولید کند، اطلس باید سه پرسش را جدا نگه دارد:

- آیا قالب خروجی معتبر بود؟
- آیا گام‌های عمومی با واقعیت‌ها و stack سازگار بودند؟
- آیا پاسخ منتخب با مرجع پس از inference یکسان شد؟

ممکن است قالب معتبر ولی جواب نادرست باشد، یا برعکس یک رقم درست بدون trace معتبر
تولید شود. یکی‌کردن این دو verdict، علت خطا را پنهان می‌کند.

## مرز نهایی برداشت

اطلس برای پاسخ به «چه داده و الگوریتمی در چه ترتیبی مصرف شد؟» ساخته شده است، نه
برای ادعای «مدل درون خود چه احساسی یا فکر خصوصی‌ای داشت؟». نتیجهٔ یک نمونه نیز
جای accuracy چندنمونه‌ای، چند seed و confidence interval را نمی‌گیرد.
