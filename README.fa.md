## چرا این پروژه ساخته شده است؟

آزمایشگاه مدل‌های هوش مصنوعی alef.ba ذیل [**برنامهٔ تحقیقاتی بین‌المللی alef.ba**](https://alef.ba) و با سه هدف توسعه می‌یابد:

۱. **آموزش شیوهٔ عملکرد مدل‌ها** — قابل مشاهده‌کردن توکن، بردار تعبیه، توجه، آموزش، نمونه‌گیری، effort استدلال، مسیریابی MoE، بازیابی، ابزار، diffusion، عامل‌ها و زنجیره‌های چندوجهی.

۲. **پشتیبانی از تصمیم‌های فنی** — ایجاد چارچوبی پایه برای انتخاب، ساخت، سفارشی‌سازی، ارزیابی یا بهره‌برداری از مدل، بدون پنهان‌کردن فرض‌ها پشت یک امتیاز واحد.

۳. **تبیین و آزمون alef.ba** — مدل‌سازی یک مسیر معنایی محدود و قابل رسیدگی، از منابع دارای شاهد تا بازنمایی میانی نوع‌دار، رندر متناسب با مقصد و رسید راستی‌آزمایی صریح.

این آزمایشگاه عمداً مدل‌های کوچک واقعی را کنار شبیه‌سازی‌های قطعی قرار می‌دهد. کاربر می‌تواند منشأ مقدارها را ببیند، یک کنترل را تغییر دهد، همان اجرا را بازپخش کند و محاسبه را از توضیح تشخیص دهد.

## وضعیت قابلیت، بخشی از رابط کاربری است

هر قابلیت عمومی باید یکی از برچسب‌های زیر را داشته باشد. این برچسب کیفیت شاهد را بیان می‌کند، نه بزرگی چشم‌انداز را.

| برچسب | معنی در این مخزن | نمونه در نسخهٔ حاضر |
|---|---|---|
| **Implemented / پیاده‌سازی‌شده** | به‌صورت محلی اجرا می‌شود و آزمون یا خروجی قابل بازرسی دارد | Transformer ده‌توکنی؛ n-gram، MLP، Transformer متراکم، scratchpad، sparse-MoE، RAG مبتنی بر SQLite FTS5 و ابزارهای allowlist؛ شبیه‌ساز پژوهشی دسکتاپ؛ کامپایلر محدود specimen در alef.ba |
| **Simulated / شبیه‌سازی‌شده** | یک مدل آموزشی صریح از فرایند است، نه سامانهٔ واقعیِ محصول نام‌برده | نمایش سه‌بعدی معماری، گردش‌کار عامل و استدلال، timelineهای diffusion و چندوجهی، سناریو و آینده‌پژوهی، نمایش abliteration |
| **External / بیرونی** | از مقاله، سند رسمی یا مخزن بالادستی توضیح داده می‌شود و اینجا اجرا نشده است | محصولات تجاری نام‌برده، خانواده‌های عمومی مدل، اتصال زندهٔ MCP/API/A2A و inference ارائه‌دهندگان |
| **Planned / برنامه‌ریزی‌شده** | جهت آیندهٔ منتشرشده است و ادعای پیاده‌سازی فعلی ندارد | بستهٔ بازپخش قابل حمل، سنجش رسمی دسترس‌پذیری، رسید امضاشده، rendererهای مقصدویژه و adapterهای زندهٔ opt-in |

پیش از توصیف یک قابلیت یا مقایسه، [قرارداد ادعا](docs/CLAIM_CONTRACT.md) را بخوانید.

## معماری در یک نگاه

~~~mermaid
flowchart LR
    S[منبع + منشأ] --> A[APIR نوع‌دار و متکی به منبع]
    A --> B[بودجه + پروفایل مقصد]
    B --> R[رندر]
    R --> V[راستی‌آزمایی I / R / U / O]
    V --> D[تصمیم + رسید]

    A -. فقط payload .-> T[HTTP / API / MCP / A2A]
    T --> ID[هویت]
    ID --> P[سیاست + رضایت]
    P --> X[اجرای مجاز]
    X --> W[شاهد بیرونی برای U / O]
    W --> V
~~~

مسیر alef.ba عمداً محدود تعریف شده است:

**منبع → APIR نوع‌دار و متکی به منبع → بودجه/پروفایل مقصد → رندر → راستی‌آزمایی/رسید**

- **I — Integrity / یکپارچگی:** آیا artifact از نظر ساختار معتبر و از نظر درونی سازگار است؟
- **R — Representation / بازنمایی:** آیا تعهدهای آن تا منبع و provenance قابل ردیابی‌اند؟
- **U — Uptake / دریافت و استفاده:** آیا گیرنده یا مدل مقصد واقعاً آن را دریافت یا مصرف کرده است؟ بدون شاهد بیرونی `UNKNOWN` می‌ماند.
- **O — Outcome / پیامد:** آیا پیامد ادعاشده در جهان بیرون واقعاً رخ داده است؟ بدون شاهد بیرونی `UNKNOWN` می‌ماند.

APIR یک بازنمایی میانی معناست. یک پروتکل می‌تواند آن را حمل کند، اما **انتقال ≠ اختیار**: HTTP، API، MCP، A2A یا JSON-RPC به‌خودی‌خود هویت، رضایت، تأیید سیاست یا اجازهٔ اجرا ایجاد نمی‌کند. جزئیات در [معماری](docs/ARCHITECTURE.md) و [قرارداد Decision Lab](docs/ALEFBA_DECISION_LAB.md) آمده است.

## اجزای monorepo

~~~text
Sample01/
├── src/digit_lm/                  # Transformer ده‌توکنی واقعی
├── tests/                         # آزمون‌های رفتاری و ایمنی Digit LM
├── reasoning-lab/
│   ├── src/reasoning_lab/         # مدل‌ها، RAG، ابزار و traceهای شفاف
│   ├── tests/                     # آزمون‌های reasoning-lab
│   └── desktop/                   # آزمایشگاه بصری Electron + Vite + Three.js
├── docs/                          # معماری، شواهد، مقایسه و پژوهش
├── data/                          # داده‌های محلی کوچک و قابل بازرسی
├── configs/                       # پیکربندی تکرارپذیر آزمایش‌ها
└── artifacts/                     # checkpoint و گزارش تولیدشدهٔ محلی
~~~

سه سطح اجرای متفاوت عمداً از یکدیگر جدا شده‌اند:

- **Digit Microscope LM — محاسبهٔ واقعی.** یک Transformer decoder-only مناسب CPU با واژگان دقیقاً `0…9`؛ مسئلهٔ رقم بعدی را آموزش می‌بیند، tensor و احتمال‌ها را نمایش می‌دهد و رفتار خارج از توزیع را قابل بررسی می‌کند.
- **Micro Reasoning Lab — اجزای واقعی و محدود.** آزمایش‌های کوچک n-gram، MLP، Transformer متراکم، scratchpad، sparse-MoE، RAG و ابزارهای allowlist همراه با traceهای مبتنی بر SQLite.
- **Desktop Visual Lab — توضیح و مقایسهٔ قطعی.** تصویرسازی‌های Electron/Vite/Three.js حالت را به نمودار تعاملی تبدیل می‌کنند. هرجا سامانهٔ واقعی بالادستی در دسترس نیست، رابط از برچسب `Simulated` یا `External` استفاده می‌کند.

## شروع سریع

### ۱. اجرای مدل زبانی ده‌توکنی

به Python 3.11 و [uv](https://docs.astral.sh/uv/) نیاز است.

~~~powershell
uv sync --frozen
uv run digit-lm run-lab --reset
uv run digit-lm predict 4 --no-trace
uv run digit-lm serve
~~~

سرویس محلی، آزمایشگاه آموزش و inference را ارائه می‌کند و به کلید API نیاز ندارد.

### ۲. اجرای آزمایشگاه استدلال

~~~powershell
Set-Location reasoning-lab
uv sync --frozen
uv run reasoning-lab build-data
uv run reasoning-lab train-all
uv run reasoning-lab verify
uv run reasoning-lab serve
~~~

پنج checkpoint خروجی‌های قابل‌بازتولید هستند و عمداً در Git نگه‌داری
نمی‌شوند. بنابراین clone تمیز باید سه فرمان آماده‌سازی بالا را اجرا کند؛ دامنه،
منشأ مولد و هش‌های دادهٔ مصنوعی در
[کارت دادهٔ Reasoning Lab](reasoning-lab/docs/fa/DATA_CARD.md) ثبت شده‌اند.

### ۳. اجرای دسکتاپ یا ساخت نسخهٔ ویندوز

به Node.js با نسخهٔ `^20.19.0` یا `>=22.12.0` نیاز است.

~~~powershell
Set-Location reasoning-lab/desktop
npm ci
npm run check
npm run dev
~~~

برای ساخت فایل portable ویندوز x64 در سیستم محلی:

~~~powershell
npm run dist:win
~~~

نسخه‌های منتشرشدهٔ ویندوز همراه checksum، هر زمان موجود باشند، باید در [صفحهٔ Releases](https://github.com/danialsamiei/alefba-ai-model-lab/releases) قرار گیرند. وجود source checkout یا موفقیت build محلی به‌تنهایی به معنی انتشار عمومی نیست.

برای خروجی مورد انتظار، دستورهای آزمون و رفع اشکال، [راهنمای شروع کار](docs/GETTING_STARTED.md) را ببینید.

## انضباط پژوهش و مقایسه

پروژه ابزارهای آموزشی و visualization را با معیار خنثیِ گستره، تعامل، کار آفلاین، سه‌بعدی‌بودن، بازپخش قطعی، منابع علمی، بسته‌بندی ویندوز و دسترس‌پذیری مقایسه می‌کند. `ND` یعنی «در منبع مستند نشده»، نه «وجود ندارد». [ماتریس مقایسهٔ تاریخ‌دار](docs/COMPARISON.md) و [فهرست منابع دست‌اول](docs/research/SOURCES.md) مبنا هستند.

سامانه‌های نام‌برده—از ChatGPT، Sora، Codex، Claude Code، Qwen و DeepSeek تا diffusion، تولید تصویر/ویدئو/صدا/کد، agent harnessها، MCP و پروژه‌هایی مانند MiroFish—فقط تا عمقی توضیح داده می‌شوند که منابع عمومی دست‌اول پشتیبانی کنند. آزمایشگاه از رفتار محصول، جزئیات محرمانهٔ پیاده‌سازی را استنتاج نمی‌کند.
